How to Read the Update Output

The log lists each attempt in britney's own terms. This page sorts them out; here is where each kind of line ends up:

Lines of britney's update output and where this page shows them
In the logWhat it meansHere
recur:A pass of britney's loop begins, with how many items it has left to try. After accepting items it goes round again, in case they made room for others.The run summary above; the number of tries on each skipped upload.
trying:Britney tries to migrate an item, or several that depend on each other at once.Every item below was tried.
accepted:Nothing new stopped installing, so britney keeps the item.The Migrated tab.
skipped:Something would stop installing, so britney backs out. Its three numbers are britney's bookkeeping: items to retry, items maybe to retry, items left in this pass.The Skipped tab.
got:How many packages would not install, per architecture, in the order britney checks them, up to the first one with a problem.The Statistics tab.
* arch:What would stop installing on the first architecture with a problem. Britney checks architectures in a fixed order ({{ run.architectures | join(", ") }}) and stops there: the ones before it passed, the ones after it were not checked and may break too. So there is one architecture per attempt."Breaks first on" and "What would stop installing".
final:, SUCCESSThe items that migrated in this run.The Migrated tab.
List of old librariesBinaries their source no longer builds that britney could not remove, because something still needs them.The Old libraries tab.

A skipped upload usually needs the packages that would break to be updated or rebuilt first, or to migrate together with it, which an archive admin can arrange with a hint. Ubuntu's guide to the update output (opens in a new tab)
